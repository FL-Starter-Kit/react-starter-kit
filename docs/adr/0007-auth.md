# 0007 — Auth: httpOnly-cookie sessions with single-flight refresh

Date: 2026-08-11

## Status

Accepted

## Decision

- **httpOnly-cookie session** established and cleared by the backend (`/api/auth/login`,
  `/api/auth/logout`). JavaScript never reads or stores the token — `localStorage`/`sessionStorage`
  for tokens is lint-banned; the frontend's `tokenStorage` only reflects the session cookie for
  expiry heuristics.
- **`GET /api/auth/me` is the source of truth** for the client session model (`SessionUser` + role).
- **Single-flight refresh**: on any 401 (except auth endpoints), `lib/auth/refreshSession.ts`
  triggers one silent refresh; concurrent failures await the same promise; the original request
  retries once (`lib/http/client.ts`). Refresh **failure is an explicit session transition**: the
  auth subsystem flips to `unauthenticated` exactly once (single-flight), clears local state, and
  `ProtectedRoute` sends the user to `/login` — no query or component discovers the dead session
  piecemeal.
- Client-side authorization is **progressive disclosure, not enforcement**:
  `ProtectedRoute`/`PermissionGate`/`RoleGate` + a static permission table
  (`lib/auth/permissions.ts`) shape the UI. The backend remains the enforcement point (mock backend
  demonstrates 403 paths).
- CSRF: designed for SameSite cookies plus backend-issued anti-CSRF token injection via the client's
  `defaultHeaders` when the backend requires it.

## Context

Alternatives: bearer tokens in `localStorage` (XSS-stealable, requires a token-refresh dance per
request, harder to invalidate server-side), or pure frontend auth state with no session endpoint
(unsafe — anything can be forged client-side).

## Consequences

- XSS cannot exfiltrate the session — the biggest single win for a browser app.
- Login/logout/refresh are real API interactions, which the MSW mock backend emulates faithfully
  (httpOnly-cookie semantics in the browser; `setActiveSession()` module state under Node where
  undici does not manage cookies).
- The refresh flow is testable and tested (`scenario.auth.expireNextRequest` drives the 401 path,
  `scenario.auth.failNextRefresh` drives the expiry transition in integration tests).
- The frontend cannot implement auth itself — a backend with session endpoints is a hard
  requirement; the mock backend is the contract for them.
